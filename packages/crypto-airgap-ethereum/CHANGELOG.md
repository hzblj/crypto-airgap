# @hzblj/crypto-airgap-ethereum

## 0.2.0

### Minor Changes

- [#1](https://github.com/hzblj/crypto-airgap/pull/1) [`8405a1f`](https://github.com/hzblj/crypto-airgap/commit/8405a1f0595ed7ab1b27e0181a2748a7f0859c8a) Thanks [@hzblj](https://github.com/hzblj)! - Every ERC-4527 data type, both ways, now that `@hzblj/crypto-ethereum` 0.3.0 signs them: legacy transactions (data type 1, with EIP-155), EIP-712 typed data as JSON (2), personal messages (3) and typed transactions of types 1, 2 and 4 (4: EIP-2930, EIP-1559 and EIP-7702, with access lists, and contract creation with `to: null`). A watch-only wallet asks with `{transaction}` of any type the adapter signs or `{typedData}` in viem's shape, and gets back a transaction ready to broadcast or a typed data signature (`kind: 'typed-data'`), each checked by recovering its signer. A signer reads the parsed transaction, its `maxFee` (`gas × gasPrice` or `gas × maxFeePerGas`), its EIP-7702 `authorizations` with the account each one delegates, and `warnings` (`CONTRACT_CREATION`, `DELEGATION`, `ALL_CHAINS_DELEGATION`); typed data is read strictly (`parseTypedData`: at most 32 levels deep, no key twice, no NUL, no fraction, integers exact), hashed by the chain, and shown as it is hashed (declared members only, integers as `bigint`, addresses EIP-55), with `NO_CHAIN_ID` when its domain names no chain. `signRequest` answers each as Keystone's firmware does: a legacy transaction with EIP-155's v in as many bytes as it takes, a typed one with the y parity, typed data and messages with v as 27 or 28; `eth-signature` now carries 65 to 72 bytes, and every one of those forms reads. `typedDataJson` writes what a request carries, `bigint`s as decimal text. A request for another chain id (the request's, the transaction's own, or the typed data domain's) is `REQUEST_MISMATCH`; typed data and messages may leave the request's chain id out, as MetaMask's and Keystone's keyrings do, which a signer on a network other than mainnet used to refuse for messages. Tested against Keystone 3's firmware signing vectors (a Seaport order and a personal message, signed to the same bytes), the request form of `@metamask/eth-qr-keyring` 3.0.1, `@keystonehq/bc-ur-registry-eth` for every data type, and viem.

  Type changes to check when upgrading: `EthereumSignRequest`'s transaction is now `ParsedEthereumTransaction`, a union on `type` with `to: Address | null` (it was an EIP-1559 request with a recipient), so read `gasPrice` or `maxFeePerGas` after narrowing on `type`, and handle a contract creation; a transaction review also has `authorizations` and `warnings`. `EthereumSignRequest`, `EthereumAirgapRequest` and `EthereumAirgapResponse` gain a `typed-data` member, so a `switch` on `kind` needs a case for it. Requires `@hzblj/crypto-ethereum` 0.3.0 and `@hzblj/nitro-crypto` 0.1.5.

## 0.1.0

### Minor Changes

- [#4](https://github.com/hzblj/nitro-crypto/pull/4) [`728e943`](https://github.com/hzblj/nitro-crypto/commit/728e9437dd4575d3d9a6d0518fd9b23c49458920) Thanks [@hzblj](https://github.com/hzblj)! - Air-gapped signing as data, in four new packages. `@hzblj/crypto-airgap` is the payload protocol and nothing around it: Uniform Resources (BC-UR v2) with Bytewords, deterministic CBOR and fountain-coded multipart parts (`createMultipartEncoder`, `createMultipartDecoder`: strings in and out, no QR, camera or timer), a typed registry, and the public account types (`crypto-hdkey`, `crypto-keypath`, `crypto-coin-info`, `crypto-eckey`, `crypto-multi-accounts`). Every decoder takes an allowlist, bounds sizes and parts, refuses seeds and private keys whatever the allowlist says, and reports stable `AirgapError` codes that never quote the input. Parts are byte for byte those of Blockchain Commons' reference implementation and `@ngraveio/bc-ur`. The chain packages bind to a chain client and check every answer against its question: `@hzblj/crypto-airgap-bitcoin` carries PSBTs as `crypto-psbt` and accounts as `crypto-account`, `@hzblj/crypto-airgap-ethereum` speaks ERC-4527 (`eth-sign-request`, `eth-signature`) for EIP-1559 transactions and personal messages, and `@hzblj/crypto-airgap-solana` Keystone's `sol-sign-request` and `sol-signature` for legacy transactions and messages. Their CBOR is byte for byte Keystone's registries'. Accounts pair as extended public keys, as Sparrow (`crypto-account`) and MetaMask's QR hardware wallets (`crypto-hdkey`, children `0/*`, the note `account.standard`) read them (`accountKey`); `watchAccount` watches any address of an account key a hardware wallet shares; a signer reads requests for any address of its account (`{fingerprint, accountPath}`) and signs them with `signRequest`, each key derived at its path and checked against the request. Tested against Keystone's firmware codec (`keystone-sdk-rust`), Keystone's and OneKey's own payloads, `@scure/bip32` and viem.
